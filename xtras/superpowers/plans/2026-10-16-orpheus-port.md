# Orpheus Synth Back End Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A C port of the Orpheus synthesizer back end (`a3s.dll`), selectable with `apollo2 --synth orpheus`, fed
from the Apollo frames through the `orpheus_bal` mapping, and equal sample for sample to the Unicorn oracle.

**Architecture:** `src/orpheus/` holds three units. `orp_data.c` is the synth's state after init at 10 kHz, captured
from the oracle and generated. `orp_synth.c` transliterates the per-frame routines (`ce70`, `e170` and its callees)
in `double`, in the original's order of operations. `orp_map.c` turns a 20-byte Apollo frame into the 16 Orpheus
parameters. `render_synthesize` picks the Holmes synth (default) or Orpheus.

**Tech Stack:** C11, MSVC 2022 (`/W4 /WX`, `/fp:precise` default, no FMA contraction); Python 3 with Unicorn,
capstone and pefile for the oracle and the generator (`xtras/orpheus/`).

**Spec:** `xtras/superpowers/specs/2026-10-16-orpheus-synth-analysis.md`. Its routine addresses and the verdict
section's mapping are binding. The disassembly comes from `python xtras/orpheus/a3s_dump.py ADDR...`.

## Global Constraints

- Audio is 10 kHz, mono, 16-bit, with no resampling anywhere. The Orpheus port supports fs = 10000 only.
- `tests/golden/*` never change, and `apollo2 -o` WAVs with the default `--synth holmes` stay byte-identical.
- Nothing under `src/` includes from `tests/`, and nothing reads the ROM or `a3s.dll` at run time. `orp_data.c` is
  generated by `xtras/orpheus/orpheus_gendata.py` and says so in its header comment.
- New suites are `SUITE` (ROM-free) in `tests/suites.h`.
- Files are UTF-8/ASCII, with LF line endings (CRLF for `*.bat`) and lines of at most 120 columns.
- The work is on branch `dsp_fix`. Stage files by explicit path, and merge only with the user's approval.
- The mapping (spec, verdict) works as follows:
  - Frequencies are the `calib.h` fits (FN `8c`; F1 `139.364 + 21.552c`; F2 `593.289 + 44.587c`;
    F3 `1877.49·e^(0.0101545c)`), computed in double, clamped to 50..4500 and rounded half up.
  - Amplitude: a code of 1 or less gives 0; otherwise `clamp(code + off, 0, 63)`. The offsets are ALF -10, A1 -10,
    A2 0, A3 -2, AHF → p8 -14 and p9 -36. p10 = p11 = 0.
  - p12 = `clamp(floor((V-1)·100/62 + 0.5), 0, 100)`.
  - p13 = `floor(F0 + 0.5)`, where F0 = `params_f0_hz(b10)` widened as `centre·(F0/centre)^CAL_F0_RANGE_GAIN`
    (with centre = `params_f0_centre`, skipped when 0) and clamped to `CAL_F0_MIN_HZ`..`CAL_F0_MAX_HZ`.
  - p14 is the DLL's integer form (`23206847`) with MSR = 50: `c = 2·p13 − ((2·p13 − (p13>>1))·50)/100`, then
    `p14 = c·100/60`, both with C integer division.
  - p15 = 0. The volume is 80, fixed: the final filter's gain is captured for 80.

## Review Focus

1. **Silence and onsets:** frames where every amplitude is 0 or 1, followed by a vowel. The output should be
   silent and then exact, with no reset drift. The stress `.par` (Task 1) starts and ends in silence.
2. **Bursts:** an unvoiced frame (p12 ≤ 1) where 2 or more amplitudes jump up injects the impulse (`340`), and it
   must land on the same sample. The stress `.par` has three bursts.
3. **Jumps and holds:** a frequency move ≥ 154 cBark, an amplitude drop ≥ 28 dB (which holds the frequency) and an
   F0 move ≥ 50 each take the jump path, not the smoother. The stress `.par` has each one.
4. **Clipping:** a frame loud enough to saturate must give 32767 / -32768 exactly where the oracle does. The
   stress `.par` has two over-range frames.
5. **Long runs:** the 1677-frame `long_clause` must not drift. Its `.pcm` is in the suite.

### Task 2: The back end, `orp_synth`

**Files:**
- Create: `src/orpheus/orp_data.h`, `src/orpheus/orp_synth.h`, `src/orpheus/orp_synth.c`
- Create: `tests/test_orpheus.c`; Modify: `tests/suites.h` (`SUITE(suite_orpheus)`), `build.bat` (add `src\orpheus`
  to PRODSRC)

**Interfaces:**
- `#define ORP_PARAMS 16`, `#define ORP_FRAME_SAMPLES 100`
- `typedef struct orp_synth orp_synth;` (defined in the header, with no heap use)
- `void orp_init(orp_synth *s);` is the state after `2320bb10` + `2320c620` + `2320c510`, from `orp_data`
- `void orp_frame(orp_synth *s, const int16_t p[ORP_PARAMS], bool first, int16_t out[ORP_FRAME_SAMPLES]);`
  is `2320ce70(p, 80, 1)` and then `2320e170(first, out)`. `first` is the engine's `[esi+0x840]`: true only for an
  utterance's first frame.
- `uint64_t orp_clipped(const orp_synth *s);` counts the samples saturated by the `e170` limiter

- [x] **Step 1: Write the failing test.** `suite_orpheus` reads each `tests/orpheus/<name>.par`, runs `orp_frame`
  (first = frame 0) and compares the result with `<name>.pcm` sample for sample. On a mismatch it reports the
  item, frame, sample, got and want, and fails. It also checks that `stress` has a nonzero `orp_clipped`.
- [x] **Step 2:** Run `cmd //c ".\build.bat test suite_orpheus"`. It is expected to fail to compile.
- [x] **Step 3:** Implement `orp_synth.c` routine by routine: `ce70`, `d080`, `d480`, `d720`, `d870`, `da30` and the
  `e170` output stage. Keep each original x87 expression's operand order, and the points where a value is stored to
  a double. `_ftol` becomes a truncation to int32; `fistp word` becomes round-half-even, behind the ≥ 32767 /
  < -32768 checks. Integer state (phase accumulators, the LCG) keeps the original's widths.
- [x] **Step 4:** Run `cmd //c ".\build.bat test suite_orpheus"`. Expected: PASS, 0 failures.

  If a mismatch remains, record the first mismatching frame and value. Compare the oracle's intermediate buffers
  (Unicorn memory) with C's at that frame. If it comes from 80-bit intermediates, carry that expression in the
  order the x87 does. Exact equality stays the bar.
