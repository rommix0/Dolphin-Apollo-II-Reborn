> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `apollo2` sound like the device the user expects. The user chose every value in this plan by ear in A/B listening tests on 2026-10-01; this plan builds those choices into the synthesizer, CLI, calibration tool and spec.

**Architecture:**
- **Pitch:** F0 uses the firmware's own pitch-period scale. The pitch movement is widened around each utterance's centre, which `render` computes.
- **Transitions:** frames flagged by the firmware (b13 bit 7) ramp their amplitudes quickly, and silent channels hold no resonator energy.
- **Filters:** a low-end peak acts on the voiced source, and a 3.8 kHz low-pass models the device's DAC filter. Both are always on in the CLI; `synth_options` can turn them off for tests only.
- **CLI:** the device's prosody setting is exposed as `--prosody`.
- **Calibration:** amplitudes are refitted against the Juno reference's male passages only.

**Tech Stack:** C11 built with MSVC 2022 through `build.bat`; Python 3.13 (numpy, scipy, librosa, matplotlib) and ffmpeg for `tools/calibrate.py`.

**Spec:** `docs/superpowers/specs/2026-09-30-software-apollo2-design.md` (revision 4; Task 7 makes it revision 5). Read §1.4 (frame format), §2 R1, §5 (synthesizer) and §7.2.

## Facts this plan relies on (established 2026-10-01 by ROM analysis and the user's listening tests)

- **The pitch scale.** b10 is a pitch *period*. The ROM routine `$B930` clamps the mark-space byte to `47 − 2·code ≤ b11 ≤ 160 − 2·code`, which only makes sense if the period is `160 − 2·code` samples at 10 kHz:
  - code 32 (the plain-corpus median) is 104.2 Hz;
  - `@F0`…`@FF` give codes 2…63, which is 64…294 Hz;
  - the old log fit (`CAL_F0_LNA/LNB`) came from a Juno snippet that contains two voices, and is wrong.
- **The firmware intonation model.** The generator at `$D129`–`$D3DD` builds each segment's pitch target:
  - `$1C27 = ($1C26>>3) + $1C25 + $1C30 + $1C23 + 105`, plus the centre;
  - accented head syllables get +15;
  - the nucleus (the last accent) gets +15 −10;
  - the nuclear tail gets −15, and the final syllable −20;
  - function words get no accent;
  - the onset after an accent gets −15;
  - there is declination.
- **The prosody setting.** At playback, `$BDD3` scales every deviation from 128 by **@R/4**:
  - `@R4` is the generator's unscaled contour;
  - the device default `@R3` is 0.75 of it;
  - `@R8`/`@R9` are ignored, because the manual's `o` is an octal digit.
- **The user's pitch choices.** Prosody `@R4` (CLI default 4), with a **pitch-range gain of 2.0** around the utterance's median pitch.
- **Thump and click mechanisms (measured):**
  - Our amplitudes multiply each resonator's *output*. Muted resonators keep ringing at the silence frame's formants, so a glide onset (W, Y) after silence overshoots 2.6–2.9× its steady level at a fast onset. The cure: clear a channel's resonator state when its gain was 0 ("mute-reset").
  - b13 bit 7 is set at stop closures (`$C0`), releases (`$80`/`$90`), onsets after silence and many vowel/sonorant boundaries:
    - a full-frame (100-sample) ramp exposes a low-frequency thump at stop closures;
    - an instant step clicks at vowel/sonorant boundaries;
    - **a 16-sample ramp** fixes both.
- **The user's sound choices:**
  - keep the **impulse source**; the shaped Rosenberg and sawtooth pulses were rejected;
  - add a **peaking filter on the voiced source: 110 Hz, Q 0.6, +10 dB**, which restores the fundamental (H1);
  - add a **4th-order Butterworth low-pass at 3.8 kHz** on the output, modelling the DAC reconstruction filter;
  - **the CLI has no switches for the filters** (user decision 2026-10-01): they are always on. `synth_options.peak_filter`/`lowpass` exist so tests can compare with and without them.
- **Remaining spectral mismatch** against the Juno's male passages (file time 5–14.4 s and 22.3–25 s): 300–500 Hz about +5 dB, 2–2.5 kHz about +5 dB, 3 kHz about −14 dB. Task 6 refits the channel levels.

```c
/* b10 is a pitch period: the ROM clamps the mark-space byte to 47 - 2c <= b11 <= 160 - 2c ($B930),
   so the period is 160 - 2*code samples (spec §1.4). */
#define F0_PERIOD_BASE 160.0f
#define F0_PERIOD_STEP 2.0f

float params_f0_hz(int code)
{
    float period = F0_PERIOD_BASE - F0_PERIOD_STEP * (float)code;
    float min_period = (float)SYNTH_RATE / CAL_F0_MAX_HZ;
    if (period < min_period)
        period = min_period;
    return clampf((float)SYNTH_RATE / period, CAL_F0_MIN_HZ, CAL_F0_MAX_HZ);
}

float params_f0_centre(const uint8_t *frames, size_t count)
{
    size_t hist[256] = { 0 }, voiced = 0, seen = 0;
    for (size_t i = 0; i < count; i++) {
        const uint8_t *f = frames + i * SYNTH_FRAME_BYTES;
        if (f[9] >= 40 && f[2] > 10) {   /* clearly voiced speech */
            hist[f[10]]++;
            voiced++;
        }
    }
    for (int code = 0; code < 256 && voiced > 0; code++) {
        seen += hist[code];
        if (2 * seen >= voiced)          /* the lower median */
            return params_f0_hz(code);
    }
    return 0.0f;
}
```

```python
    """b10 codes -> Hz through the firmware period scale (params.c params_f0_hz)."""
```

```c
#include <math.h>
#include "test.h"
#include "synth/biquad.h"
#include "synth/params.h"

#define TEST_PI 3.14159265358979

/* |H| at hz measured from biquad_step's impulse response: checks the difference equation against
   the coefficients. */
static double measured_db(biquad *f, double hz)
{
    enum { N = 4096 };
    double re = 0.0, im = 0.0;
    biquad_reset(f);
    for (int n = 0; n < N; n++) {
        double y = biquad_step(f, n == 0 ? 1.0f : 0.0f);
        re += y * cos(2.0 * TEST_PI * hz * n / SYNTH_RATE);
        im -= y * sin(2.0 * TEST_PI * hz * n / SYNTH_RATE);
    }
    return 10.0 * log10(re * re + im * im);
}

/* The voiced-source low-end peak the user chose: 110 Hz, Q 0.6, +10 dB. */
static void test_peaking(void)
{
    biquad f;
    biquad_peaking(&f, 110.0f, 0.6f, 10.0f, (float)SYNTH_RATE);
    CHECK(fabs(biquad_gain_db(&f, 110.0, SYNTH_RATE) - 10.0) < 0.05);
    CHECK(fabs(biquad_gain_db(&f, 0.0, SYNTH_RATE)) < 0.05);       /* unity at DC ... */
    CHECK(fabs(biquad_gain_db(&f, 5000.0, SYNTH_RATE)) < 0.05);    /* ... and at Nyquist */
    CHECK(fabs(biquad_gain_db(&f, 1000.0, SYNTH_RATE) - 0.38) < 0.1);
    CHECK(fabs(biquad_gain_db(&f, 2000.0, SYNTH_RATE)) < 0.2);
    CHECK(fabs(measured_db(&f, 110.0) - biquad_gain_db(&f, 110.0, SYNTH_RATE)) < 0.05);
}

/* Two RBJ low-pass sections with the Butterworth Q pair form a 4th-order Butterworth low-pass. */
static void test_butterworth_lowpass(void)
{
    biquad a, b;
    biquad_lowpass(&a, 3800.0f, 0.5411961f, (float)SYNTH_RATE);
```

```c
/* Second-order IIR sections from R. Bristow-Johnson's Audio EQ Cookbook, normalised so a0 = 1:

    float b0, b1, b2, a1, a2;
    float z1, z2;
} biquad;

void biquad_reset(biquad *f);
float biquad_step(biquad *f, float x);
```

`src/synth/biquad.c`:
```c
#include <math.h>
#include "synth/biquad.h"

#define PI_F 3.14159265358979f

static void set(biquad *f, float b0, float b1, float b2, float a0, float a1, float a2)
{
    f->b0 = b0 / a0;
    f->b1 = b1 / a0;
    f->b2 = b2 / a0;
    f->a1 = a1 / a0;
    f->a2 = a2 / a0;
    biquad_reset(f);
}

void biquad_peaking(biquad *f, float f0_hz, float q, float gain_db, float fs)
{
    float a = powf(10.0f, gain_db / 40.0f);
    float w = 2.0f * PI_F * f0_hz / fs;
    float alpha = sinf(w) / (2.0f * q), c = cosf(w);
    set(f, 1.0f + alpha * a, -2.0f * c, 1.0f - alpha * a, 1.0f + alpha / a, -2.0f * c, 1.0f - alpha / a);
}

void biquad_lowpass(biquad *f, float f0_hz, float q, float fs)
{
    float w = 2.0f * PI_F * f0_hz / fs;
    float alpha = sinf(w) / (2.0f * q), c = cosf(w);
    set(f, 0.5f * (1.0f - c), 1.0f - c, 0.5f * (1.0f - c), 1.0f + alpha, -2.0f * c, 1.0f - alpha);
}

void biquad_reset(biquad *f)
{
    f->z1 = 0.0f;
    f->z2 = 0.0f;
}

float biquad_step(biquad *f, float x)
{
    float y = f->b0 * x + f->z1;
    f->z1 = f->b1 * x - f->a1 * y + f->z2;
    f->z2 = f->b2 * x - f->a2 * y;
    return y;
}

double biquad_gain_db(const biquad *f, double hz, double fs)
{
    double w = 2.0 * 3.14159265358979 * hz / fs;
    double nr = f->b0 + f->b1 * cos(w) + f->b2 * cos(2.0 * w), ni = -(f->b1 * sin(w) + f->b2 * sin(2.0 * w));
    double dr = 1.0 + f->a1 * cos(w) + f->a2 * cos(2.0 * w), di = -(f->a1 * sin(w) + f->a2 * sin(2.0 * w));
    return 10.0 * log10((nr * nr + ni * ni) / (dr * dr + di * di));
}
```
